# Station favorites and local RF memories

Favorites are station-side, versioned records with stable UUIDs. RF slots are
optional fixed strings 1–999, without leading zeroes. Slot 1 is **\*51**, not
\*501, and needs no terminating # from the radio. Existing \*3 node dialing is
unchanged. A prefix overlap such as slots 1 and 12 is rejected atomically.

## Local-only enable prerequisite

The installer **does not change existing AllStar function access**. Save a
favorite without enabling RF to use it normally. RF enable is fail-closed until
the effective node, includes, templates, and caller access can be verified.

The audited node 60670 currently shares local/link/phone function tables and
has `5=macro`. Macro execution does not retain trustworthy caller provenance.
Simply adding an ostensibly local helper is therefore **not safe**: a link or
phone could invoke the same new macro. Enabling is intentionally blocked on
that station pending owner review of a configuration isolation plan.

An owner-reviewed plan must:

1. Give the physical receiver node its own functions and macro sections, without
   changing the effective existing local commands, existing macro definitions,
   `funcchar`, or \*3 connection command. Digital/other nodes must not share or
   inherit these newly isolated tables.
2. Explicitly name separate link, phone and dphone function sections. Preserve
   their existing non-macro/non-cmd commands, but remove macro and cmd access.
   **This changes existing remote control capability and needs specific owner
   approval**; this release does not silently perform it. Other indirect custom
   command paths must be reviewed before enabling.
3. Keep the local `5=macro` binding. Reload the reviewed configuration and verify
   effective runtime state before enabling any RF slot in the owner UI.

Each enabled slot adds only delimited managed entries to the verified local
function and macro sections. Slot N expands to a fixed `DND` helper function;
the helper has only two fixed arguments: slot and saved-generation digest.
It accepts no destination, URL, shell fragment, or variable trailing digits.
The Unix socket is restricted to the Asterisk UID and is not a TCP endpoint.
The backend rechecks the current saved enabled slot, generation, parrot and
connection gates before using the same non-bridging destination dispatcher.
Changing or deleting a favorite never renumbers another slot. A stale helper
cannot connect a newly changed destination because its generation no longer
matches the station store.

## Apply, rollback, and recovery

Only an explicit owner save enables entries. Application holds the favorites
store lock through configuration update and store commit. Every changed config
file has a `.allmode-rf-backup`; writes use fsync and atomic rename. An apply,
reload or store exception restores original files and reloads app_rpt. A crash
between files or store commit is fail-closed at recall through generation
checking; after recovery, review and save again to reconcile managed entries.
Power-loss atomicity across multiple configuration files is not claimed.

Missing/ambiguous includes, unsupported executable directives, duplicate
sections/keys, inherited table consumers, or remote macro access prevent RF
enable. Ordinary disabled favorites remain usable when RF configuration is
unavailable. If disabled-save cleanup cannot parse the config, obsolete helper
entries may remain but cannot recall disabled favorites. Repair the config and
save again to remove the managed entries.

`install-runtime.sh` creates a setgid allmode:asterisk runtime directory through
systemd-tmpfiles and gives the web service access to that directory only. The
root-owned Python helper is installed with the other app modules. There are no
new third-party packages. Existing station config and optional audio settings
are not reset. No voice feedback or RF transmissions are generated by the test
suite; automatic feedback is deliberately off (including telemdefault=0).

Upstream behavior references:
- https://allstarlink.github.io/adv-topics/macros/
- https://github.com/AllStarLink/app_rpt/blob/master/apps/app_rpt/rpt_functions.c
- https://github.com/AllStarLink/app_rpt/blob/master/apps/app_rpt/rpt_config.c

Validation includes mocked config apply/reload/store rollback, includes and
inheritance, bidirectional prefix conflicts, unsafe remote access, strict slot
validation, and generation identity. Real Unix-socket tests are explicitly
skipped where the execution sandbox denies AF_UNIX; that is not a hardware or
RF verification. Never test by keying a radio or connecting a real node without
separate owner authorization.

### Explicit reviewed isolation command

The narrowly approved change disables **only remote \*5 macro dispatch**, while
preserving local \*3 and \*5 and every other remote command. Any other macro alias,
remote `cmd`, alternate-function table, or remote-base configuration stops the
plan and requires fresh review. Existing sections/includes are not deleted.

Read the exact plan on the station (no changes):

```sh
sudo python3 /opt/allmode/rf_memory_isolate.py --node 60670
```

Review `removed_remote_macro_commands`, `node_overrides`, `new_sections`, and the
source hashes. Then apply only that reviewed digest as a separate administrator
action (never from the installer):

```sh
sudo python3 /opt/allmode/rf_memory_isolate.py --node 60670 --apply-reviewed-digest REVIEWED_PLAN_DIGEST
```

Changed source invalidates the digest. Apply writes a separate
`.allmode-rf-isolation-backup`, validates the resulting effective configuration,
and reloads app_rpt. Failure restores the backup and attempts reload. This is a
configuration operation, not an RF test or connection. No favorite is enabled by
this command; enabling remains a separate explicit owner save.

### Station-regeneration topology limit

Automatic station reconfiguration currently supports an RF-enabled station whose
physical node section is in the main `rpt.conf`. Effective function/macro includes
are inspected, but a physical station node placed in an included file is rejected
with a specific error **before any live configuration changes**. Such a topology
requires manual reconciliation/review; the installer does not move the node or
erase its include. This limitation is covered by an isolated regression fixture.

### Storage-failure recovery

A directory-sync error can occur after an atomic rename is already visible. The
config transaction registers each attempted write before rename and restores its
prior contents on failure. The favorites store likewise restores the exact prior
bytes, or removes the new file if no prior store existed. Fault-injection tests
exercise both late-failure cases and the combined store/config transaction.

If restoring the favorites snapshot also fails, a private
`favorites.json.recovery-required` file records the prior serialized snapshot
(`previous: null` means the file was originally absent). All favorites reads,
saves and RF recalls fail closed while this marker exists. An administrator must
repair storage, restore that recorded snapshot or verified backup, and only then
remove the marker and review/reapply the dial plan. If storage cannot even retain
the marker, persistence cannot be guaranteed; the running store instance remains
blocked and the storage fault requires administrator recovery. No successful
save or power-loss durability is claimed after such errors.

Feedback remains silent: there is no spoken acknowledgement, unkey detection or
voice scheduling in this candidate. IPC receipt and controller/log events mean
requested/dispatched, not verified connected. Existing status UI supplies the
actual connection state; telemetry settings remain unchanged.
